# 固定多轮查询验收

本套件验证 `ConversationSession` 的连续请求，数据源为固定本地 MySQL 的公开 `ecommerce-v1` 合成数据。它不评估生产数据库、跨会话记忆或任意结果等价性。

## 案例与独立预期

`conversations-v1.json` 包含6段会话，每段3轮，前3段为开发集，后3段为首次运行前固定的验收集。覆盖跨月比较、支付日期与状态替换、取消明细筛选、空集后扩大时间窗口、背景数据窗口变更和切换主题。题目、SQL 和预期行在第一次模型运行前固定。

预期由独立编写者从 `src/db_agent/ecommerce.py` 的公开固定账本及闭式生成规则手工推导，整合者再次逐题核对。没有运行生成器计算答案，没有让候选 SQL 自己充当基准。例如二月固定已支付订单为2、4、6，毛额90+0+50=140；一月订单为1、7，客户6只出现在一月，因此两月比较必须重新包含该客户，不能仅使用上一轮二月客户集合。明细重新取消数量筛选后需找回商品2；空集扩大到3月21日后应出现退款81、82；取消支付时间筛选后的背景订单集合与上一轮不相交。

完整题目、独立推导、参考 SQL 和各轮预期见 JSON。开发集和验收集共用公开业务字典，只有首轮在用户题目之前附加字典；后两轮只发送原始追问。参考 SQL、oracle、预期行和上一轮查询结果不会注入模型。

## 运行协议

在默认预算与风险阈值、固定模型配置、同一产品源码下，预定运行：

```bash
uv run python scripts/evaluate_conversations.py --mode sql --split dev --repeat 1
uv run python scripts/evaluate_conversations.py --mode sql --split holdout --repeat 1
uv run python scripts/evaluate_conversations.py --mode agent --split dev --repeat 1
uv run python scripts/evaluate_conversations.py --mode agent --split holdout --repeat 2
```

SQL 基线共18轮，真实 Agent 开发集9轮、验收集18轮。开发集如暴露缺陷，可修复后记录新的源码快照和完整重跑；旧结果保留。验收集开始后若用其失败调整产品，必须降格为回归，不能继续称作独立新题验收。每次重复从新会话开始；前一轮失败后的追问仍进入同一控制器并得到依赖停止，不能重置、补全题目或注入参考 SQL 继续得分。

每轮必须只有一次完整成功的业务查询，结果与独立预期相同，回答等于可信报告的程序渲染，需求合同的请求哈希绑定实际完整会话输入。只有三轮全部通过才计为一段成功会话。空集可以成功；拒绝、模型失败、缺少证据、依赖停止和未执行项都保留在计划分母中。模型调用失败不等于业务数据错误，分别统计类别。

报告写入被 Git 忽略的 `outputs/evals/<id>.json`，权限0600，从开始即登记全部计划项并逐轮保存。报告记录案例、产品源码和配置摘要，以及合成数据的 SQL、结果、运行 ID 和失败码；普通产品事件仍不记录用户原文或查询行值。模型 endpoint 仅保存哈希，不保存凭据或原始提供方异常。

每轮前后及结束检查案例与源码哈希。输入变化、取消或中止会留下 `incomplete` 报告，未运行项仍在分母中。保存失败不能宣称已完成验收。一次 SQL 基线成功只证明当前固定数据与参考查询，离线协议测试也不能替代真实多轮业务结果。
