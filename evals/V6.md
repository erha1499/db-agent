## 新题与独立推导

每题详细推导保存在 JSON 的 `oracle`；只有不变的业务字典和题目 `prompt` 进入模型，参考 SQL、预期、oracle 与冻结哈希不进入模型消息。

| 新题 | 业务区别与人工预期 |
| --- | --- |
| 重复支付原额／退款额组合 | 六笔成功退款对应的金额对为 `(50,10)`、`(50,20)`、两次 `(50,25)`、两次 `(40,20)`。按金额对分组后筛选至少两笔，返回 `(40,20,2)`、`(50,25,2)`。相同数值的不同退款不能去重；后一组来自同一支付的两次退款，前一组来自不同支付。 |
| 成功支付从未出现任何退款 | 成功支付为 12、22、23、41、61、71、81、82；退款引用 23、61、71、81、82，包含 pending 或 failed。只保留支付 12／订单1／100、22／订单2／40、41／订单4／0。71 虽无成功退款，也必须排除；22 不能因同订单其他支付有退款而被误排除。 |
| 历史截止点尚未完成的退款 | 退款21在2月3日12:05完成；退款22在2月4日12:00申请、12:05完成。截至2月4日12:03，仅22已申请但尚未完成，即使它当前为 succeeded。其他退款尚未申请。输出当前状态和原始申请、完成字段，不把现在状态当历史状态。 |
| 已支付类别的数量与成交净额 | 已支付明细按类别为：books 1行／1件／50；electronics 3行／6件／230；gift 1行／1件／0；home 2行／2件／40；sports 1行／4件／60。订单2商品1的净额为70，不能用目录单价或折前80替代；gift 零值组必须保留。 |
| 成功退款指向失败支付的异常 | 成功退款实际父支付仅23、61、81、82，均 succeeded；失败支付为11、21、31。正确完整关联得到 COUNT=0、SUM=NULL。只按订单关联会把订单2的失败支付21与指向成功支付23的退款错误配对，制造异常。 |
| 背景创建与支付窗口交集 | 客户1000的第k笔订单创建于12:00:00+k秒、支付晚60秒，ID为1000+1000k、金额100。创建窗口限定k=0..59，支付窗口限定k=30..59；交集30笔／3000，最小ID31000、最大60000。不能将两个条件取并集或互换字段。 |
| 多件明细仅占整单一部分 | 多件行分别为订单1净额80／整单100，订单2净额70／整单90，订单7为60／60，订单8为80／80。严格小于整单且大于0只保留订单1、2，quantity均2；后两行相等必须排除。订单2要返回折后70。 |
| 同订单尝试金额不全相同 | 订单2全部尝试金额为失败90、成功40、成功50：3笔，最小40、最大90、总尝试金额180。只有它满足 MIN<MAX；订单1的100／100与订单8的40／40虽然有多次尝试，均不符合。提前过滤失败支付会改错笔数、最大值及合计。 |

金额按 Decimal 字符串比较，`SUM(quantity)` 的精确整数 Decimal 也保留字符串，COUNT 及本范围内的 ID 为整数。时间使用 DATETIME 原值，无时区后缀；空聚合的 NULL 不补零。行顺序只在参考查询明确排序时要求一致，无排序聚合仅比较完整结果。

所有题都先限定固定 `id` / `order_id` 范围，或客户1000的既有索引范围，并保留当前静态检查、普通 EXPLAIN 和扫描／连接／排序审核阈值。新题不靠 LIMIT 掩盖风险。复合关系来自实际结构，不以字段名推测，也不能据外键声明认定所有历史数据都已验证一致。

## 预定运行与失败口径

产品冻结且固定 `--suite v6` 入口集成后，按以下计划首次运行，不补跑挑绿：

| 模式 | dev | 新 holdout |
| --- | --- | --- |
| 固定参考 SQL | 48题 × 1轮 | 8题 × 1轮 |
| 真实 Agent | 48题 × 1轮 | 8题 × 2轮 |

每题仅一次真实查询尝试。模型生成、独立意图与最终复核仍共享4次模型调用、6次工具调用、60秒总时限，每次输出1024 token；自动补取结构也计入工具预算。不额外传入参考 SQL，不用手写候选代替真实 Agent。

旧退款余额参考 SQL 原样保留，因此它仍可能得到既有 REVIEW；这项已知失败必须留在旧 SQL 开发集分母中。新增关系信息后，真实 Agent 能否自行形成完整关联并完成业务结果，需要另看真实调用、最终 SQL、计划和返回值，不能由手写 SQL 验证代替，也不能把拒绝了查询算成已完成查数。

```bash
uv run python scripts/evaluate_ecommerce.py --suite v6 --mode sql --split dev --repeat 1
uv run python scripts/evaluate_ecommerce.py --suite v6 --mode sql --split holdout --repeat 1
uv run python scripts/evaluate_ecommerce.py --suite v6 --mode agent --split dev --repeat 1
uv run python scripts/evaluate_ecommerce.py --suite v6 --mode agent --split holdout --repeat 2
```
