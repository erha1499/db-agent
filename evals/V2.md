# 电商验收套件 v2

**历史版本：本版 24 题现已参与开发回归或失败诊断，两个 split 的后续运行都标记 `exposed_regression`。新的独立验收见 [v5](V5.md)；下文“新题”描述的是 v2 创建时的状态。原 JSON 与历史报告保持不变。**

套件版本为 `ecommerce-eval-v2`，业务数据版本仍为 `ecommerce-v1`。要求固定本地导入配置为 1000000 订单、100000 客户、10000 商品、seed `20260910`，不重建或修改已冻结数据以适配问题。

v1 的全部 16 题已在开发或失败诊断中暴露。因此原始 [v1 文件](ecommerce-v1.json) 保留原字节，旧失败报告不覆盖；后续 v1 的 dev 和 holdout 都标记 `exposed_regression`。这包括修复后跑通旧题的结果，不能再称其为未参与调整的留出验收。

[v2 文件](ecommerce-v2.json) 包含：

- **dev：16 道回归题。** 保留 v1 的题目 ID、SQL、独立预期和原问题文本，将 split 统一改为 dev；旧 ID 中的 `holdout_` 前缀仅用于追溯历史，不代表当前角色。
- **holdout：8 道新验收题。** 使用不同的筛选和指标，覆盖商品销售、客户分组过滤、支付状态、退款细节、日期区间、缺失金额、背景索引查询和拒绝边界。预期来自人工数据协议与独立算式，不来自模型答案或重复执行候选 SQL。

两个 split 共用显式公开业务字典：订单状态、支付与退款的 `succeeded` 含义、对应时间字段及统计粒度。字典由套件提供，不注入产品系统提示；不包含候选 SQL 或预期答案。原 v1 有些问题只写“成功”而未提供 VARCHAR 状态枚举，模型需要额外探索数据才能知道字面值，和一次业务查询的约束冲突。v2 明确这些必要业务输入；补齐字典不等于允许修改权限或增加预算。

先冻结产品提示词、通用运行规则、v2 题目及字典，再执行首轮模型验收。可预先选择一次运行或 `--repeat 2`，但不能根据首轮结果追加运行后只挑通过结果。失败应保留并报告；一旦根据新题失败修改产品或提示词，本版新题也转为开发回归，不能继续宣称其未参与调整。公开小样本、共享数据和手选题目仍限制结论，不代表统计无偏的广泛能力测量。

```bash
uv run python scripts/evaluate_ecommerce.py --suite v2 --mode sql --split dev --repeat 1
uv run python scripts/evaluate_ecommerce.py --suite v2 --mode sql --split holdout --repeat 1
uv run python scripts/evaluate_ecommerce.py --suite v2 --mode agent --split dev --repeat 2
# 首次新验收的重复次数必须在查看该轮结果前确定：
uv run python scripts/evaluate_ecommerce.py --suite v2 --mode agent --split holdout --repeat 2
```

报告分别记录数据版本、套件版本、split 角色、源码哈希、完整套件文件哈希、所选案例哈希、公共字典哈希和实际输入哈希；Agent 的输入哈希对应“字典 + 空行 + 题目”，SQL 模式对应直接提交的参考 SQL。套件还记录首次验收前产品系统提示词的哈希。报告不会由一个通过分数证明输入未暴露；是否用题目做过调整仍须结合保留的版本、首轮失败与任务记录判断。

所有执行、权限、预算、错误分类和产物隐私规则沿用 [评测说明](README.md)。`--suite` 接受 `v1` 至 `v5`，默认 `v1` 兼容旧命令；没有从命令行指定任意案例文件的入口。SQL 与模型模式分别验收，未运行的模式不能视为通过。
