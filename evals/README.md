# 电商业务评测

**当前使用 [v2 套件](V2.md)。v1 的 16 题已全部用于开发或失败诊断，后续重跑均为 `exposed_regression`。原始 [v1 案例文件](ecommerce-v1.json) 和失败报告保持原样，旧 `holdout` 名称不再表示未暴露验收。**

使用 `--suite v2` 选择 v2：16 道回归题属于 dev，新增 8 道题属于 holdout；业务数据仍是 `ecommerce-v1`。省略 `--suite` 保持 v1 兼容。报告分别记录 suite、suite_version、dataset_version 和 split_role。

以下介绍 v1 的原始组织方式与两版本共用的执行规则。

本目录是公开合成数据的固定任务集，不含企业数据。16 题分为开发集 8 题和冻结验收集 8 题；两种运行模式使用同一任务口径，但证据不同。

```bash
uv run python scripts/evaluate_ecommerce.py --mode sql --split dev --repeat 1
uv run python scripts/evaluate_ecommerce.py --mode agent --split dev --repeat 1
uv run python scripts/evaluate_ecommerce.py --mode sql --split holdout --repeat 1
uv run python scripts/evaluate_ecommerce.py --mode agent --split holdout --repeat 3
```

除默认 v1 的 `--suite` 外，其余参数必须显式指定。`sql` 模式把公开候选 SQL 交给真实 `QueryService`，不调用模型；`agent` 模式向真实 Agent 提供题目 prompt；v2 另附公开业务字典，不注入参考答案或另附参考 SQL。一般业务题由模型生成 SQL；拒绝和大扫描题的原始 SQL 本身就是题目输入。评测通过现有工具和可观测接口取得真实调用报告，不能用候选 SQL 代替模型调用。Agent 模式会消耗配置提供方的额度，只有明确选择此模式才调用。每题是独立会话，案例要求一次业务查询；元数据查询不算业务查询。

运行目标固定为 `127.0.0.1:13306/db_agent` 的 `db_agent_reader`，表范围只能缩小到配置已授权表与六张 `ec_*` 表的交集。缺授权会停止，不会自动改 `.env` 或数据库权限。评测不创建、修改或清理数据。写入和跨库题只把输入提交到产品预检入口，预期在业务 SQL 派发前拒绝。

先由管理员核验 `ecommerce-v1` 默认规模的导入完成清单：1000000 订单、100000 客户、10000 商品，以及生成协议规定的明细、支付与退款行数。评测不会使用 root，也不会把管理员清单表加入模型白名单。低 ID 的 8 个固定订单与背景 ID `>=1000` 隔离；背景索引题的预期仅适用于默认百万订单规模。评测报告不单独证明全库行数或导入完整性，必须与加载器核验记录共同解读。

## 独立预期与任务范围

[案例文件](ecommerce-v1.json) 每题包含业务问题、SQL、涉及的授权表、人工口径依据和固定预期。预期不是重复执行候选 SQL 的结果，也不读取生成器运行时统计：

- 创建月的已支付订单毛额：一月 `160.00`、二月 `140.00`、三月 `80.00`；退款状态仍属于已支付订单。
- 到账月的成功支付额：一月 `60.00`、二月 `190.00`、三月 `130.00`；失败和待支付流水不计。二月有 4 条成功支付流水，对应 3 个订单。
- 成功退款按 `completed_at`：二月 `30.00`、三月 `90.00`，失败和待处理退款不计；一笔支付可以对应多次退款，不能重复累计支付金额。
- 默认背景订单有 `999992` 条，零基位置中每个 1000 的倍数专属客户 1000，共 `1000` 笔，每笔 `100.00`，独立闭式预期为 `100000.00`。

固定边界的金额和时间来自人工业务协议，背景 cohort 用闭式计数；它们仍是合成数据 oracle，不是生产业务知识。日期列为 DATETIME，字段本身没有时区；fixture 的业务约定按 UTC 解释，不代表任意 DATETIME 都能这么处理。

结果按列位置比较，允许别名变化；无 ORDER BY 的多行结果按保留重复行的多重集比较，不强加行序。严格核对 `status`、`decision`、执行状态、行值、完整性及截断原因。截断题只把服务端行数预算降低为 2，不放宽策略；大扫描带 LIMIT 的正确答案是 REVIEW，任何结果返回或派发迹象均作为错误放行。配置不能提高默认扫描、连接或排序审核阈值来让评测通过。

## 冻结与证据边界

先用 dev 修复实现和提示，再对固定 holdout 运行验收。公开可见不代表可反复查看 holdout 失败后继续宣称它未参与开发：一旦用它调参，本版验收题应视为已使用，保留失败报告，重新设计未参与调整的新版本后才能宣称新的留出验收。本目录没有自动训练或调参功能。

每次报告写到忽略目录 `outputs/evals/<uuid>.json`，含题目数、实际尝试分母、重复次数、错误分类、每题查询证据、源码/案例哈希、依赖版本及模型配置；API key、数据库密码和原始模型回答不写入报告。为定位失败，评测产物明确保存本次捕获的 SQL 与公开合成数据结果；产品 `RunRecord` 仍不记录 SQL 或行值，评测报告不应作为通用业务数据导出接口。失败退出码为 1，配置或案例错误为 2，中断为 130。

预期拒绝题还检查实际提交的是题目指定 SQL，仅忽略首尾空白和一个末尾分号；其他 SQL 恰好被 BLOCK 不能代替本题边界验证。自然语言查数题不做 SQL 文本等价要求。一次查询的动作约束也检查工具调用次数与报告缺失，不能把工具调用但没有报告当成已验收成功。

错误分类分别为数据错误、解释错误、错误放行、预算、环境；一题可能同时属于多个分类。业务结果与最终回答分别判定：回答检查确认它与可信查询报告的程序渲染一致，不能把此项包装成开放式语言理解、解释语义或任意 SQL 等价性验证。渲染器本身的日期、NULL、截断和注入边界由其独立单测验证。

只报告确实运行的模式、split、分母与重复次数。单次 SQL 通过不证明真实模型通过，开发集通过不证明冻结集通过，一次 smoke 不证明稳定正确率；本地合成百万行也不是 TB 级压测或生产安全保证。
