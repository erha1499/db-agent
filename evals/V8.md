## 新题与独立推导

每题完整预期及推导也保存在 JSON 的 `expected` 和 `oracle`。这些内容不进入模型消息，模型业务输入仍只有原共享字典与对应 `prompt`。

| 新题 | 独立推导与区别 |
| --- | --- |
| `v8_orders_with_high_average_line_quantity` | 按订单统计平均每行件数，严格超过1.5才返回。订单1、2均为(2+1)/2=1.5，必须排除；订单3、4、5、6均为1。订单7、8分别为4、2，按平均值降序返回7、8，每组1条明细，总件数分别4、2。不能先过滤大件数行再计算平均值。平均值预期为Decimal字符串 `4.0000`、`2.0000`，总件数为 `4`、`2` 的Decimal字符串。 |
| `v8_equal_successful_amounts_across_orders` | 比较不同订单的两笔成功支付，保留金额完全相同的每个无序组合。金额40出现在支付22／订单2、81／订单8、82／订单8，产生22–81、22–82；81–82因同订单排除。金额50出现在23／订单2与61／订单6，产生23–61。其余成功金额只出现一次。三个组合按前、后支付ID排序，不能把两组40金额组合去重。 |
| `v8_same_customer_order_amount_changes` | 同一客户较早、较晚订单的每一对原金额变化。客户1的订单1→2，100→90，差值−10；客户2的订单3→6，50→50，差值0。客户2的取消订单3仍要纳入，因为本题不筛状态；其他客户不足两张订单。这里只比较创建先后与原总额，不比较到账或净退款。 |
| `v8_repeated_product_lines_within_order` | 检查同一订单是否将同一商品拆成多条明细。订单1、2各有商品1与2各一条，其余固定订单均只有一条明细，所以所有订单／商品组的条数都是1，满足至少两条的组为空。相同商品跨订单重复不算重复组合；空分组结果也不是一行COUNT=0。 |
| `v8_catalog_sku_suffix_and_price` | SKU为 `EC-SKU-` 加8位补零商品ID。固定商品中，末位为2或5的只有商品2、5，其目录价分别20、15，都满足不高于20。按价格升序返回商品5／`EC-SKU-00000005`／15，再商品2／`EC-SKU-00000002`／20，SKU前缀与补零必须保留。 |
| `v8_attempted_amount_exceeds_order_gross` | 全部尝试金额超过原订单金额的重试统计。订单1失败100+成功100=200，比原额100多100，共2笔；订单2失败90+成功40+成功50=180，比原额90多90，共3笔。其他订单的尝试合计等于原额，包括订单8的40+40=80。订单1必须入选，尽管它的两次尝试金额相同；这与旧题“尝试金额是否变化”不同。原订单金额每组只取一次，尝试金额不是现金到账。 |
| `v8_background_paid_time_page` | 客户1000按支付时间降序，跳过前两笔再取三笔。闭式公式为k=0..999，ID=1000+1000k，支付时间12:01:00+k秒，金额100。降序跳过k999、998后返回997、996、995，即ID998000、997000、996000，时间分别12:17:37、12:17:36、12:17:35。结果是指定页面的完整3行，不代表客户总订单数，也不属于服务端截断。 |
| `v8_background_region_population_with_missing` | 客户ID1000..1044对应i=0..44，共45人。i模11为0时region为NULL，得到0、11、22、33、44共5人；其余按i模4分配east、west、north、south。原余数组为12、11、11、11人，被替换的余数为0、3、2、1、0，留下四个地区各10人。按人数降序、地区升序，返回east10、north10、south10、west10、NULL5。 |

金额及金额差按两位小数的精确字符串保留，负差值不取绝对值。COUNT及本范围内的ID为整数。MySQL 对精确数值的 SUM、AVG 返回 DECIMAL，官方整数 AVG 示例为四位小数；本题据此记录平均件数和总件数的表示。参考：[聚合函数返回类型](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)、[精确数学示例7](https://dev.mysql.com/doc/refman/8.4/en/precision-math-examples.html)。这只核对类型，实际业务数字来自上表账本与算术；没有用浮点近似或取整得到预期。
