# 本机多身份接入与验收

Web 现在必须登录。可信身份来自本机管理员维护的私有文件，浏览器提交用户名和密码后取得短期服务端会话；请求不能自报可信 user_id、数据库目标、表白名单或批准信息。

目标环境固定为本机隔离合成环境：一个 Python 进程、一个现有 MySQL 数据源、多个 Web 身份。CLI 仍属于运行它的本机操作系统用户，不是面向这些 Web 身份开放的接口。此交付不包含公网部署、生产接入、企业 SSO、操作系统用户隔离或多进程服务。

## 管理员准备

先完成 README 中的本机 MySQL 配置与公开合成 fixture。`.env` 中 `DB_AGENT_MYSQL_ALLOWED_TABLES` 是所有身份表权限的上限；业务连接始终使用现有只读 `db_agent_reader`。添加 Web 用户不会新建 MySQL 账号，也不授予该账号更多权限。

```bash
uv sync --locked
uv run db-agent db check
uv run python scripts/manage_web_users.py set alice --display-name Alice \
  --tables orders customers --allow-model --model-tables orders
uv run python scripts/manage_web_users.py set bob --display-name Bob --tables customers
uv run python scripts/manage_web_users.py list
npm --prefix frontend ci --registry=https://registry.npmjs.org
npm --prefix frontend run build
uv run db-agent web --identity-file outputs/web/identities.json
```

`set` 交互输入两次新密码，要求 12–128 字符，不回显，不把密码放入命令参数；重新 `set` 某用户会完整替换该用户的表范围、模型设置和密码。只有显式 `--allow-model` 才启用模型，`--model-tables` 必须是该用户 `--tables` 的子集。未启用模型的用户仍可直接查询 SQL、诊断 SQL、查看结构和管理自己的知识。`list` 不打印密码摘要。

默认身份文件是忽略的 `outputs/web/identities.json`，仅接受当前操作系统用户拥有的普通文件，权限必须为 `600`；拒绝符号链接、无效字段、重复用户名和超出数据库上限的表。脚本原子替换私有文件，文件缺失或无效时拒绝接入，不自动回退为匿名单用户模式。使用 `--file` 可管理一个明确指定的其他私有文件；启动时用相同的 `--identity-file`。

```bash
uv run python scripts/manage_web_users.py disable bob
```

当前没有 Web 管理员角色或自助注册。能够读写 `.env`、身份文件、SQLite 或进程内存的操作系统用户就是本机管理员，文件系统不用于隔离同一操作系统账号下的恶意程序。不要把管理脚本、配置目录或未鉴权 CLI 包装成远程接口。

## 用户入口与权限

浏览器打开 `http://127.0.0.1:8000`。登录页和当前身份面板说明允许表、模型表范围和数据使用边界。三个模式分别是：

| 模式 | 表范围 | 模型使用 | 数据库行为 |
| --- | --- | --- | --- |
| 智能查询 | 当前身份的 `model_tables` | 使用一个配置模型及既有三阶段核对 | SQL 经完整预检后仅 ALLOW 执行 |
| SQL 查询 | 当前身份的 `allowed_tables` | 不调用 | 同一 QueryService/连接器重新预检并执行 |
| SQL 诊断 | 当前身份的 `allowed_tables` | 不调用 | 仅普通 EXPLAIN，不执行 SELECT |

表权限同时限制元数据、计划与业务行。授权一个表意味着可以读取当前支持的全部列和行；本版本没有列级/行级规则。页面隐藏或禁用按钮只是交互提示，服务端会重新判断权限。

智能查询会发送用户原文、成功查询的历史原始请求、显式引用的已确认知识、模型授权范围内取得的结构、SQL 与计划摘要。只把允许该模型使用的内容输入智能查询。服务端不会加载其他用户的请求、结果、知识、数据库凭据或模型密钥作为上下文，查询返回行仍由程序直接显示，查询工具轮后不再请求模型。用户自行键入的文字无法被系统自动证明不含敏感信息；模型表权限限制服务端取证范围，不是文本脱敏器。

## 会话、撤销与隔离

登录使用带随机盐的 [scrypt](https://docs.python.org/3/library/hashlib.html#hashlib.scrypt) 摘要核对密码，服务端保存随机会话的摘要，登录有效期一小时且不滑动延期；重启后必须重新登录。Cookie 使用 HttpOnly、SameSite=Strict、`/api` 路径，当前本机 HTTP 不设置 Secure。登录、退出均保留 Host、Origin、跨站请求及专用请求头检查。最多 10 次登录尝试/分钟（单进程共享）、128 个未过期登录，不提供“用户名是否存在”的不同错误。

除认证接口外，每个 API 同时核对 Cookie 和页面已验证的 `X-DB-Agent-Session`。该头不是认证凭据，作用是拒绝其他标签页切换 Cookie 后仍携带旧身份的请求。前端在退出、401、跨标签页切换及会话核对变化时卸载工作区，清空内存历史、结果、草稿、结构和知识，取消并丢弃旧身份在途响应；也在每 15 秒及页面恢复可见时重新核对。

历史、运行、停止、结果取回/分析/导出与知识都绑定服务端的“用户 + 数据源/账号/表范围 + 授权代际”。即使两个用户使用相同 reader、相同表权限，也不能根据另一个用户的 ID 取回、修改或撤销资源。全进程仍只允许一个运行任务；其他身份看不到该任务 ID 或内容，只收到忙碌提示。请求 ID 防重复机制仍只用于当前会话，不能成为跨用户取回凭据。

身份、数据库、模型或预算配置每次 API 访问及连接器关键派发前核对；后台每 200 毫秒检查失效登录并请求取消任务。任何观察到的配置变化都会持久化一个新授权代际、撤销全部旧登录，并使旧范围的历史/结果/知识不可访问。恢复旧配置也不会重新获得已经撤销代际中的资源。配置损坏或不可读时停止访问；存储故障不能当作授权通过。已派发 SQL 的服务器终态仍可能 unknown，不声称服务端已确认取消。

旧数据保留在本机 SQLite 中供管理员管理，不自动删除、迁移或重新授权。上线本功能前的匿名 Web 历史与 CLI 知识不会分配给第一个登录用户。管理员缩小数据库白名单时，应先相应收窄身份文件；无效配置可在本机编辑修正，不能通过扩权来恢复访问。

## 知识管理

登录后在知识面板创建指标口径、声明关系或 SQL 模板草稿，必须包含来源、来源版本、有效期和失效条件。完整阅读草稿后勾选人工确认，前端提交所展示内容的精确 digest。确认过程查询真实授权结构；供模型使用的知识按模型实际可见的结构范围确认，避免更宽直接查询范围内的外键改变指纹。

只有已确认、未过期且表范围适合当前模型的条目可以插入 `[[knowledge:id]]`。每轮必须显式引用；保存和确认不会自动影响所有会话。查询前仍核对知识生命周期与当前结构，撤销后不继续沿用。拥有直接查询权限但不在模型表范围内的知识可以保存和管理，不能发送给模型。知识不是授权、通用语义等价证明或最新业务数据。

## 验证入口与证据口径

```bash
uv run pytest tests/test_web.py tests/test_web_identity.py -q
npm --prefix frontend run build
npm --prefix frontend run test:e2e
uv run python scripts/evaluate_web_identities.py --run
uv run python scripts/evaluate_web_identities.py --run --model --browser
```

单元/浏览器合同使用明确的合成服务或 HTTP 替身。独立验收脚本显式启动真正的 loopback HTTP 服务，两个身份通过真实 API 与现有本地 MySQL 查询固定公开 fixture；只有 `--model` 才调用配置模型，`--browser` 才运行真实浏览器。输出写入忽略的 `outputs/web-identity`，记录源码哈希、计划分母、实际结果及失败，不重新运行失败案例替换首次结果。脚本不创建业务表，不使用 root，不修改数据库权限。

本机合成验收与远端 CI 的结果分别记录在交付记录；不能据此声称互联网服务或生产多租户环境已经安全。
