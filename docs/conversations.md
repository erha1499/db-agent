# 会话内多轮查询

本阶段让连续查询保留用户明确的业务口径，例如「查二月订单毛额 → 按客户拆分 → 比较一月和二月」。每轮仍是一次新的受控 Agent 运行；历史不会携带表权限、计划批准或可复用的执行凭证。

## 会话输入与运行边界

`run_agent_observed` 和 `run_agent` 新增可选关键字参数 `previous_requests`。省略或传入 `None` 时保持原单轮行为；只有显式传入服务端维护的 `list[str]` 才启用会话模式。运行入口统一构造包含 `prior_requests` 和 `current_request` 的 JSON 请求包，主生成、独立需求提取和最终复核使用同一个包；需求记录的请求哈希也绑定该完整输入。

当前请求始终作为字符串编码，即使它含有相同前缀或看似历史的 JSON，也不能闭合外层结构。原单轮入口不会根据正文前缀自动启用会话模式。输入是用户数据，不因被封装而提升为系统指令。

上下文只包含原始用户请求，最多12条（包含本轮），序列化后的 UTF-8 文本最多24576字节，包含前缀、JSON和转义。超限在模型 HTTP 请求之前拒绝；不自动丢弃最早一轮、不截断字符串、不让模型摘要替换用户原意。应用需让用户重置会话并重新完整说明需求。

三阶段的共同要求：

- 延续相关且未修改的用户口径，当前明确修改覆盖对应旧要求；完整的新主题或要求原样执行的新 SQL 独立处理。
- 只处理当前任务，不重放历史查询。当前仅解释、诊断或编写 SQL 时，不因历史查数要求而执行 SQL。
- 不把助手回复、生成 SQL、业务行、旧结构或计划报告作为历史输入。「上一结果第三行」「这些客户」「上述 SQL」缺少实际对象时要求完整重述，不能猜测。
- 比较月份或其他范围时，从当前数据库重新查询所需各部分；不能仅查询新范围就声称完成比较，也不能用未提供的旧行值计算。

模型与工具仍由 LangChain 调度。每轮共享原有4次模型调用、6次工具调用、60秒总时限，单次模型请求默认30秒，请求输出上限配置1024 token，禁用自动重试；每轮重新取得结构并进入原执行入口预检。输出 token 的提供方计数限制见[已知验收边界](ecommerce.md#2026-09-11-v8-最终业务验收)。

上下文隔离与两次语义检查不保证模型总能正确理解自然语言；确定性代码继续负责权限、SQL规则、计划与执行限制。会话连续性必须用独立业务预期和真实结果验收。

## 交互式使用

配置好本地 `.env` 的模型、数据库和表白名单后运行：

```bash
uv run db-agent session
```

每行提交一个查询，`/help` 查看帮助，`/reset` 清空历史，`/exit` 或 EOF 退出。例如先完整描述二月订单的范围、有效状态和金额口径，再输入「按客户拆分，金额降序」，随后输入「保留口径，列出每个客户一月、二月金额和二月减一月的差值」。两个月的数据均重新查询；具体 SQL 仍受现有语法和风险阈值限制。

`ConversationSession` 将模型、数据源、账号、表白名单和预算配置绑定到当前实例。每轮重新创建连接器、HTTP 客户端和运行记录；运行中不能同时提交或重置。修改配置后应退出并重新启动命令。退出或进程结束即丢失请求会话，没有恢复接口；[业务知识](knowledge.md)通过独立持久化和本轮显式引用实现跨新会话复用，不回放旧回答或结果。

仅当全部查询调用均有完整成功报告，且结果未截断，才保留本轮原始用户请求。零行结果可以保留。异常、取消、拒绝、截断、缺少报告或没有完成查询会暂停查询链，必须 `/reset` 后完整重述，不能自动退回较早的成功口径。只做解释或诊断也会暂停查询链；独立问答可以使用原 `chat` 命令。

模型运行中按 Ctrl-C 会等待原运行的取消清理，再返回提示符并要求重置；连接清理完成不证明服务器 SQL 已取消。输入提示符处按 Ctrl-C 退出，退出码130。当前上下文上限为12轮、24576字节，超限不会自动摘要或删掉旧条件。

## 验收与限制

显式上下文 API、三阶段协议和 CLI 会话控制已实现；离线验证覆盖历史隔离、单轮兼容、失败后重置、并发拒绝以及真实 SIGINT 触发的取消清理。全量测试1380通过，单独开关的数据库隔离测试另3/3通过，Ruff与diff检查通过。

2026-09-11在本地百万订单合成库完成6段三轮场景验收：参考 SQL 18/18；真实 Agent 固定验收集两次合计18/18轮（每次9/9），开发集首次8/9、原样追加回归9/9。包括「二月汇总 → 客户拆分 → 同时查一月/二月并比较」，以及替换日期口径、移除筛选、空集后扩大范围和切换主题。首次跨月比较因独立需求提取超时未执行 SQL，该失败保留，不被后续通过覆盖。所有真实 Agent 尝试合计35/36轮、11/12段会话通过。

这证明约定合成场景可以连续查询，不能推导任意业务口径、任意SQL支持或生产可靠性。模型理解仍可能失败；结果指代、跨进程恢复与长期业务记忆不在本阶段范围内。完整案例、独立预期、来源哈希、运行ID和失败说明见[固定多轮验收记录](../evals/CONVERSATIONS.md)。
