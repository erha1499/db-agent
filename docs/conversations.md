# 会话内多轮查询

本阶段让连续查询保留用户明确的业务口径，例如「查二月订单毛额 → 按客户拆分 → 比较一月和二月」。每轮仍是一次新的受控 Agent 运行；历史不会携带表权限、计划批准或可复用的执行凭证。

## 会话输入与运行边界

`run_agent_observed` 和 `run_agent` 新增可选关键字参数 `previous_requests`。省略或传入 `None` 时保持原单轮行为；只有显式传入服务端维护的 `list[str]` 才启用会话模式。运行入口统一构造包含 `prior_requests` 和 `current_request` 的 JSON 请求包，主生成、独立需求提取和最终复核使用同一个包；需求记录的请求哈希也绑定该完整输入。

当前请求始终作为字符串编码，即使它含有相同前缀或看似历史的 JSON，也不能闭合外层结构。原单轮入口不会根据正文前缀自动启用会话模式。输入是用户数据，不因被封装而提升为系统指令。

上下文只包含原始用户请求，最多12条（包含本轮），序列化后的 UTF-8 文本最多24576字节，包含前缀、JSON和转义。超限在模型 HTTP 请求之前拒绝；不自动丢弃最早一轮、不截断字符串、不让模型摘要替换用户原意。应用需让用户重置会话并重新完整说明需求。

三阶段的共同要求：

- 延续相关且未修改的用户口径，当前明确修改覆盖对应旧要求；完整的新主题或要求原样执行的新 SQL 独立处理。
- 只处理当前任务，不重放历史查询。当前仅解释、诊断或编写 SQL 时，不因历史查数要求而执行 SQL。
- 不把助手回复、生成 SQL、业务行、旧结构或计划报告作为历史输入。「上一结果第三行」「这些客户」「上述 SQL」缺少实际对象时要求完整重述，不能猜测。
- 比较月份或其他范围时，从当前数据库重新查询所需各部分；不能仅查询新范围就声称完成比较，也不能用未提供的旧行值计算。

模型与工具仍由 LangChain 调度。每轮共享原有4次模型调用、6次工具调用、60秒总时限，单次模型请求默认30秒，请求输出上限配置1024 token，禁用自动重试；每轮重新取得结构并进入原执行入口预检。输出 token 的提供方计数限制见[已知验收边界](ecommerce.md#2026-09-11-v8-最终业务验收)。

上下文隔离与两次语义检查不保证模型总能正确理解自然语言；确定性代码继续负责权限、SQL规则、计划与执行限制。会话连续性必须用独立业务预期和真实结果验收。
